5. Rate limit, new `apps/api/src/core/middleware/rate-limit.ts`: `rateLimit(policy: "write" | "media_upload" | "listening_progress" | "ai_import")`, must run after `requireAuth`. Key `${policy}:${userId}`. One statement via `prisma.$queryRaw`: `INSERT INTO rate_limit_buckets (bucket_key, window_start, count) VALUES ($key, to_timestamp(floor(extract(epoch from now()) / $w) * $w), 1) ON CONFLICT (bucket_key, window_start) DO UPDATE SET count = rate_limit_buckets.count + 1 RETURNING count, window_start`. `count > limit` → `DomainError(429,"RATE_LIMITED")` + header `Retry-After` = seconds until `window_start + w`. Apply `write` to every POST/PUT/PATCH/DELETE under `/api/studio` and `/api/script-workflows`, except routes with a specific policy (media-assets POST → `media_upload`; import POST → `ai_import`; progress PUT → `listening_progress`).
6. Idempotency, new `apps/api/src/core/middleware/idempotency.ts`: `idempotency()` placed after `requireAuth` + `rateLimit`, before `zValidator`, on exactly the nine POST routes of contract §0 (+ none else).
   - Header `Idempotency-Key` must parse as uuid v4 → else `DomainError(400,"IDEMPOTENCY_KEY_REQUIRED")`.
   - Body: `await c.req.text()` (cached by Hono, so `zValidator` still reads it). Non-empty body that is not valid JSON → `DomainError(400,"BAD_REQUEST","Malformed JSON body")` before claiming. `request_hash` = SHA-256 hex of `METHOD\nc.req.path\n` + stable JSON (keys sorted recursively) of the parsed body (empty body → `""`).
   - Claim: `prisma.idempotencyKey.createMany({ data: [{ userId, key, method, route: \`${c.req.routePath} ${c.req.path}\`, requestHash, status: "IN_PROGRESS", expiresAt: now + idempotency.ttl_hours }], skipDuplicates: true })`. `count === 1` → run `await next()`.
   - `count === 0` → load the row by `(userId, key)`; not found (a concurrent retryable failure just deleted it) → retry the claim once, then answer 409 `IDEMPOTENCY_REQUEST_IN_PROGRESS`. Found: hash differs → 422 `IDEMPOTENCY_KEY_REUSED`; `COMPLETED` → return stored `response_status`/`response_body` with `Content-Type` = `application/problem+json` when status ≥ 400 else `application/json`, `Location: response_location` (if any) and `Idempotent-Replayed: true`; `IN_PROGRESS` younger than `idempotency.lock_timeout_seconds` → 409 `IDEMPOTENCY_REQUEST_IN_PROGRESS` + `Retry-After: <lock timeout seconds>`; older → `updateMany({ where: { id, status: "IN_PROGRESS", createdAt: { lt: cutoff } }, data: { createdAt: now, expiresAt: now + ttl, requestHash } })`, `count === 1` → run `next()`, else 409 as above.
   - After `next()` (Hono's compose already turned thrown errors into `c.res` via `onError`): read `c.res.clone()` JSON; status ≥ 500 or body `code` in `RETRYABLE_ERROR_CODES` → delete the row; otherwise update to `COMPLETED` with status, body, `Location`.

Slug, new `apps/api/src/core/slug.ts`: `toSlug(text, maxLength)` = NFD, strip combining marks, `đ/Đ → d`, lowercase, non-`[a-z0-9]` → `-`, collapse/trim `-`, cut to `maxLength`; empty result → `"n-a"`. `randomSlugSuffix()` = 4 chars from `[a-z0-9]` via `crypto.getRandomValues`. `insertWithUniqueSlug(base, tryInsert: (slug) => Promise<boolean>)`: try `base`, then `${base.slice(0, max-5)}-${suffix}` up to `slug.max_attempts`; exhausted → `DomainError(409,"SLUG_CONFLICT")`. `tryInsert` implementations use `db.<model>.createMany({ data: [{ id: crypto.randomUUID(), slug, … }], skipDuplicates: true })` and return `count === 1` (ON CONFLICT DO NOTHING never aborts the surrounding transaction; never catch P2002 inside a transaction).
