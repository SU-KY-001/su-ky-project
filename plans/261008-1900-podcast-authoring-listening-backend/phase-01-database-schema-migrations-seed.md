# Phase 1 — Database: schema rewrite, migrations, seed

1. Delete the old dev data: `docker compose down -v` then `docker compose up -d postgres` (run from repo root; `compose.yaml` defines service `postgres`, image `postgres:18-alpine`).
2. Rewrite `packages/db/prisma/schema.prisma` to the 33 tables (DBML + deviations 1–7). Translation rules:
   - Model names PascalCase singular, `@@map("<dbml table>")`; every column `@map("<snake_case>")`; enums PascalCase with `@@map("<dbml enum>")`, values as in DBML.
   - **Keep every existing Prisma field name** of `User`, `Session`, `Account`, `Verification`, `WorkflowRun`, `WorkflowStep`, `StepVersion`, `WorkflowEvent`, `ScriptPublication` (Better Auth's adapter and `prisma-script-workflow.repository.ts` use them) and only add `@map`: e.g. `banExpires @map("ban_expires_at")`, `impersonatedBy @map("impersonated_by_id")`, `WorkflowEvent.type @map("event_type")`. `User.role` becomes `String @default("user") @db.VarChar(16)` (non-null); add `totalXp Int @default(0) @map("total_xp")`. `WorkflowRun` adds `seriesId String? @db.Uuid` (relation to `Series`, `onDelete: SetNull`) and `focusHint String? @db.Text`.
   - uuid PKs: `String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid`. Workflow tables keep `Int @id @default(autoincrement())`. `text[]` → `String[] @default([])`; `bytea` → `Bytes`; `char(1)` → `@db.Char(1)`; `date` → `@db.Date`; `smallint` → `@db.SmallInt`; `bigint` → `BigInt`.
   - `onDelete` exactly as DBML notes (cascade/restrict/set null). Unique and normal indexes with the DBML `name` via `map:`.
   - `user_weekly_mission_items` uses `@@id([userWeeklyMissionId, contentId])`; `system_configs` uses `key String @id`.
3. Scripts cutover (remove `db push` everywhere): in `packages/db/package.json` delete `db:push`, add `"db:deploy": "bun --env-file=../../.env run prisma migrate deploy"` and `"db:test:reset": "bun --env-file=../../.env.test run prisma migrate reset --force"`; in root `package.json` and `turbo.json` replace `db:push` with `db:deploy` (cache false); in `Makefile` replace target `db-push` with `db-deploy`.
4. Migration uses the standard Prisma flow (generated SQL folders under `packages/db/prisma/migrations/`, applied with `prisma migrate deploy`). Run `bun run --cwd packages/db db:migrate -- --name init --create-only` to generate `prisma/migrations/<ts>_init/migration.sql`, then add to that same file the SQL Prisma cannot generate:
   - Prepend: `CREATE EXTENSION IF NOT EXISTS unaccent; CREATE EXTENSION IF NOT EXISTS pg_trgm;` and the function
     `CREATE OR REPLACE FUNCTION immutable_unaccent(text) RETURNS text LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS $$ SELECT public.unaccent('public.unaccent'::regdictionary, $1) $$;`
   - Append every constraint Prisma cannot express, with DBML-style names (`<table>_<desc>_check`, `_key`, `_idx`): all CHECKs listed in DBML notes (users.role IN ('user','moderator','admin'); users.total_xp >= 0; historical_periods years; series years per deviation 1; media_assets `status <> 'READY' OR (duration_ms > 0 OR kind = 'IMAGE')`; episode_narrations `narrator_entity_id IS NULL OR narration_type = 'FIRST_PERSON'` and `(script_publication_id IS NULL) = (script_publication_episode_no IS NULL)` and `script_publication_episode_no BETWEEN 1 AND 3`; quizzes 1..100; quiz_options label IN ('A','B','C','D'); quiz_attempts 0..100; mission_templates target_count >= 1 AND xp_reward >= 0; weekly_missions `EXTRACT(ISODOW FROM week_start_date) = 1`; idempotency_keys status IN ('IN_PROGRESS','COMPLETED')); partial uniques `sources_isbn_key ON sources(isbn) WHERE isbn IS NOT NULL`, `quiz_options_question_id_correct_key ON quiz_options(question_id) WHERE is_correct`; partial index `series_status_active_idx ON series(status) WHERE deleted_at IS NULL`; the four GIN trigram indexes of deviation 7 (`USING gin (immutable_unaccent(lower(title)) gin_trgm_ops)`).
   - Apply with `bun run --cwd packages/db db:deploy` (dev and every other environment use `migrate deploy`; later schema changes repeat: edit `schema.prisma` → `db:migrate -- --name <change> --create-only` → hand-add SQL if needed → `db:deploy`).
   - Drift guard: Prisma cannot represent the partial indexes (`sources_isbn_key`, `quiz_options_question_id_correct_key`, `series_status_active_idx`) or the expression GIN indexes, so every later `--create-only` will emit `DROP INDEX` for them. Delete those `DROP INDEX` lines from the generated `migration.sql` before `db:deploy`. In `schema.prisma` do NOT put `@unique` on `sources.isbn` (it would create a second full unique index).
